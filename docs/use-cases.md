# ユースケース別プロンプト集

このスキルで Jira を確認するときの、聞き方の例を集めたものです。[README](../README.md) には導入と基本的な使い方を書いたので、ここでは目的別のプロンプトを、そのまま貼って使える形で並べます。

各項目は「目的」「プロンプト」「返ってくるもの」「注意」の4つでできています。プロンプトの中のプロジェクトキーや日数は、自分の環境のものに置き換えてください。

前提として、2つだけ覚えておいてください。

- 回答は、あなたの認証情報が見える範囲から集められます。課題が回答に出てこない場合、「存在しない」のではなく「権限の外」かもしれません。
- スキルは、対象範囲・読み取った件数・一覧が打ち切られたかどうかを明示します。回答にそれが無ければ、聞き直してください。
- 対象を特定の課題だけに絞りたいときは、プロンプトに課題キーを並べてください（例: 「対象は ABC-1 と ABC-2 だけ」）。ヘルパーの `--keys`／環境変数 `JIRA_ISSUE_KEYS` でサーバー側に絞り込みがかかります。指定しなければ限定されません。

---

## 1. 朝の確認 — 自分の担当と期日

**目的** — Jira の画面を開かずに、今日手を付けるべき課題を把握する。

**プロンプト**

```
Jira のスキルを使って、私の担当の未完了課題を期日順に見せてください。
期限を過ぎているものと、今日が期限のものを分けて教えてください。
```

**返ってくるもの** — 担当課題の一覧（期日順）と、期限超過・今日が期限の切り分け。

**注意** — 期日が未設定の課題は期限の判定に出てきません。期日未設定も見たいときは、その旨を付け加えてください。

## 2. 朝会の材料 — standup

**目的** — 朝会で話す「昨日終わったこと、今日進めること、困っていること」の材料をそろえる。

**プロンプト**

```
Jira のスキルを使って、朝会の材料を集めてください。私の担当について、
直近24時間に完了したもの、進行中のもの、期限超過と今日が期限のものを
分けて見せてください。
```

**返ってくるもの** — 3区分の一覧です。そのまま朝会の発言の順番（終わったこと → 進んでいること → 期日が迫っていること）に使えます。

**注意** — 「直近24時間」は実行した時刻基準です。朝会の前に実行してください。

## 3. 週次報告の材料 — weekly

**目的** — 週次報告に使う、期間固定の要約を作る。

**プロンプト**

```
Jira のスキルを使って、週次報告の材料を集めてください。直近7日に
完了したもの、新規に作られたもの、未完了のまま期限を過ぎているものを、
私の担当分について分けて見せてください。対象期間は明示してください。
```

**返ってくるもの** — 直近7日の3区分の一覧です。判定の定義が毎回同じなので、週同士を比べられます。

**注意** — プロンプトの文面は、週が変わっても変えないでください。プロジェクト全体で集めたいときは、プロジェクトキーを指定して聞いてください。

## 4. プロジェクト概況

**目的** — プロジェクト全体がどのくらい進み、どこに期限超過があるかを把握する。

**プロンプト**

```
Jira のスキルを使って、プロジェクト ABC の概況を教えてください。
ステータス区分ごとの件数と、期限を過ぎている未完了課題の一覧を
見せてください。
```

**返ってくるもの** — 未着手／進行中／完了の件数と、期限超過の一覧です。

**注意** — 件数は見える範囲での数です。Cloud では件数の数え上げに打ち切り（1000件）があり、その場合は「以上」と表示されます。

## 5. 期限超過の掘り下げ

**目的** — 期限超過の一覧から、個別の課題がどういう状況か（コメントまで含めて）を確認する。

**プロンプト**

```
Jira のスキルを使って、プロジェクト ABC で期限を過ぎている未完了課題を
挙げてください。そのうえで、超過日数が大きいものから3件、課題の詳細と
直近のコメントを見せてください。最後にコメントが書かれた日時も
教えてください。
```

**返ってくるもの** — 期限超過の一覧と、個別課題の詳細・直近コメントです。

**注意** — 期限超過は事実の抽出です。遅れている理由は、課題とコメントに書かれた内容からだけ判断し、書かれていないことは推測しないよう付け加えると確実です。

## 6. 停滞課題の洗い出し

**目的** — 長く更新がなく、止まっているかもしれない課題を見つける。

**プロンプト**

```
Jira のスキルを使って、私の担当で14日以上更新のない未完了課題を
見せてください。更新日の古い順に並べてください。
```

**返ってくるもの** — 停滞候補の一覧です。

**注意** — 「更新がない」は事実だけを示します。実際に止まっているかは、課題を開いて直近コメントを確認してから判断してください。日数は `--days` 相当としてプロンプトで指定できます（例: 30日）。

## 7. JQL 検索 — 自由な絞り込み

**目的** — 定型コマンドに無い条件で課題を探す。

**プロンプト**

```
Jira のスキルを使って、次の JQL で検索してください。
project = ABC AND resolution = Unresolved AND duedate is EMPTY
期日が未設定の未完了課題が対象です。件数と一覧を見せてください。
```

**返ってくるもの** — JQL に一致する課題の一覧です。

**注意** — JQL はそのまま実行されます。条件の意味（この例では「期日未設定」）をプロンプトに書いておくと、結果の解釈がぶれません。

## 8. 課題の詳細とコメント確認

**目的** — 1件の課題について、現状と経緯をまとめて把握する。

**プロンプト**

```
Jira のスキルを使って、課題 ABC-123 の詳細を見せてください。
ステータス、期日、担当、優先度、更新日と、直近のコメント5件を
教えてください。
```

**返ってくるもの** — 課題の主要項目と直近コメントです。Cloud ではコメントは ADF からテキストに抽出されて表示されます。

**注意** — コメントは直近の分だけが対象です。古い経緯が必要な場合は Web 画面で確認してください。

## 9. アクセス確認 — この認証情報で何が見えるか

**目的** — 他の確認を信じる前に、接続と版を確かめる。

**プロンプト**

```
Jira のスキルを使って、接続を確認してください。接続先が Data Center か
Cloud か、サーバーの版数、私が誰として認証されているかを教えてください。
```

**返ってくるもの** — 版（DC／Cloud）、サーバーの版数、認証ユーザーです。

**注意** — 他のユースケースはすべてこの接続の可視範囲を引き継ぎます。DC の実バージョンが分かるのはこの確認です。初回接続時は結果を控えておいてください。
