# 確認レシピ — 判定の定義と限界

期限超過・停滞・朝会・週次で使う判定の定義を固定し、レポート間で数字や一覧の意味がずれないようにするためのもの。確認の中心は期日・ステータス・コメントである。

## 基本の考え方

- 未完了は `resolution = Unresolved` で判定する。ステータス名（環境ごとに異なる日本語／英語の名前）には依存しない。
- 進捗の区分はステータスの `statusCategory`（`To Do`／`In Progress`／`Done`）で見る。個別のステータス名は表示用に併記する。
- 期日は `duedate`（日付のみ）の比較で判定する。「今日」は実行環境の日付である。

## 判定の定義

| 項目 | 定義 |
|---|---|
| 期限超過 | 未完了 かつ `duedate` が今日より前。期日順に並べる |
| 今日が期限 | 未完了 かつ `duedate` が今日。`standup` では期限超過とまとめて「期限超過・今日が期限」として出す |
| 停滞 | 未完了 かつ 最終更新（`updated`）が N 日より前（`stale --days N`、既定 14 日）。更新日の古い順に並べる |
| 完了（直近） | `resolved >= -1d`（standup）／`resolved >= -7d`（weekly）。完了日は `resolutiondate` |
| 新規（直近7日） | `created >= -7d` |
| 進行中 | ステータス区分が `In Progress` かつ未完了 |
| プロジェクト概況の件数 | プロジェクト内でステータス区分ごとの件数。Cloud では数え上げに 1000 件の打ち切りがあり、その場合は「以上」と表示される |

## 材料集めの進め方（基本形）

1. **朝会（standup）**: 自分の「完了（直近24時間）／進行中／期限超過・今日が期限」の3区分を出す。話す順番は「終わったこと → 進んでいること → 期日が迫っていること」が基本形。
2. **週次（weekly）**: 「完了（直近7日）／新規（直近7日）／期限超過（未完了）」の3区分を出す。期間は直近7日で固定し、週同士を比べられるように聞き方を変えない。
3. **問題の掘り下げ**: 期限超過・停滞の一覧から気になる課題を `issue KEY` で開き、直近コメントで「最後に何が書かれたか」を確認してから報告する。ステータスと期日だけでは理由は分からない。

## 限界（レポートに必ず添える）

- 見える範囲は認証ユーザーの権限の範囲だけである。全プロジェクトの集計ではない。
- 期日が未設定の課題は期限超過にも「今日が期限」にも現れない。期日未設定そのものを問題として扱う場合は、`search --jql "... AND duedate is EMPTY"` のように別途検索する。
- 停滞は「更新がない」という事実だけを示す。止まっている理由は課題とコメントで確認するもので、この判定だけでは分からない。
- コメントは課題詳細で取得した範囲（直近の数件）だけが対象である。コメント総数が多い課題では、古い経緯は Web 画面で確認する。
- Cloud の件数集計はページングによる数え上げで、1000 件で打ち切る。打ち切られた件数は下限として扱う。
- 日付の境界は実行環境のタイムゾーンに依存する。朝会・週次の材料は、実行した日を明記して残す。
